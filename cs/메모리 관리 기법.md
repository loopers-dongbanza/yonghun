✅ 메모리 관리의 전체 흐름 요약
1️⃣ 프로세스는 “물리 객체”가 아니다

프로세스는 논리적 실행 단위

우리가 보는 힙/스택/데이터/코드 영역도 실제 RAM이 아니라 가상 주소 공간 설계도

2️⃣ 커널이 먼저 메모리 구조를 설계한다

프로세스 생성 시 커널은 다음을 수행한다:

가상 주소 공간 구성

페이지 테이블 생성

물리 메모리는 아직 없음

즉, 공간만 확보해두고 실제 메모리는 나중에 요청될 때 준다.

3️⃣ 실제 실행은 “접근 시 할당(Demand Paging)”

CPU가 어떤 가상 주소에 접근

MMU가 페이지 테이블을 참조해 가상→물리 주소 변환

물리 프레임 없으면 그때 RAM에 올림

✅ 필요할 때만 메모리를 써서 효율적

4️⃣ MMU는 주소 변환 담당 하드웨어

변환 과정:

CPU가 VA 전달

VA를 페이지 번호 + 오프셋으로 분리

TLB 조회

페이지 테이블 조회

물리 주소 생성

권한/유효성 확인

RAM 접근

➡️ CPU는 물리 주소를 모른다, MMU가 전담

5️⃣ 왜 가상주소를 쓰는가?

보안(물리 주소 노출 방지)

프로세스 간 메모리 독립성

더 큰 메모리처럼 보이게 하는 추상화

효율적인 메모리 관리

➡️ VA만으로는 어느 프로세스 것인지 알 수 없다 → 페이지 테이블 필요

6️⃣ 페이징의 구조

페이지 번호: 어떤 페이지인가

오프셋: 페이지 내부 좌표

물리 주소는 프레임 시작 주소 + 오프셋

✅ 오프셋은 물리 주소 선택과 무관, 단순 위치 계산용

7️⃣ RAM이 부족할 때 등장 — 페이지 교체 알고리즘

대표 정책:

FIFO

Optimal

LRU

Clock

역할: 어떤 페이지를 RAM에서 내보낼지 결정

✅ 실행 흐름과 무관, 오직 RAM 부족 시만 발생

8️⃣ “프로세스 생성”과는 직접적 연관 없음

프로세스는 커널이 따로 생성

RAM은 실행 과정에서 필요한 페이지만 빌려줌

페이지 교체는 실행 도중 메모리 경쟁이 생길 때만 동작

✅ 생성 단계와 교체 알고리즘은 별개
